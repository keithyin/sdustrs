symmetric DUST · perfect intervals

Pareto 前沿是怎么长出来的

一个窗口里，从右端向左可以切出几十个候选子区间：长度不同、重复配对数也不同。 最后只有少数几个进入 perfect 列表。留下谁、丢掉谁，可以完全画在一张二维图上： x 轴是区间长度，y 轴是区间密度。所谓 Pareto 前沿，就是这张图上那条从左下往右上爬的台阶， 每一格都代表一次“密度纪录”。

X axis

区间长度

L

区间包含的 3-mer 个数。所有候选共享同一个右端 finish，起点越往左，L 越大。

更短更长
Y axis

区间密度

ρ = r / L

区间内相同 3-mer 的无序配对数 r 除以长度 L。向上更密，门控线在 ρ = T/10。

下方更稀上方更密

一般定义：给定候选集合和两个目标——最小化长度 L、最大化密度 ρ。若不存在另一个候选在两个目标上都不差、且至少一个更好， 该候选就是 Pareto 最优的；所有这样的点构成 Pareto 前沿。在这张图上，前沿是一条只能向右上走的台阶。

01
the two axes

先把两条轴钉死：x 是长度，y 是密度

这张图最容易画错的两件事：把 x 轴当成基因组坐标，把 y 轴当成配对数 r。它们都不是。

x 轴：区间长度 L

代码里每次向左吃进一个 3-mer，new_len = size - i - 1 就增加 1。这个 L 就是候选区间包含的 3-mer 个数；换成碱基跨度是 L + 2。所有候选的右端都固定在窗口右缘，所以“长度”等价于“起点向左伸到多远”。

方向要注意：向右是变长，在这个目标上是变差。前沿从左下往右上走，不是常见的“左上更好”。

y 轴：密度 ρ = r / L

r 是区间内相同 3-mer 的无序配对数：每一对位置上的 3-mer 相同，就贡献 1。 它不是“重复 3-mer 的个数”，所以 ρ 可以大于 1。比如一段 poly-A 的 L 个 3-mer， 两两都相同，r = L(L−1)/2，密度约为 (L−1)/2。

密度把“配对数更多”的收益和“区间更长”的代价放进同一个尺度：一个点 (L, r) 的密度， 就是原点连到它的斜率。

最容易错的一点 y 轴不是 r。如果直接把配对数 r 当 y 轴，所有候选都会随着向左延长而“更高更右”， 没有哪个点会被另一个点支配，所谓前沿就退化成整条候选折线。必须用比值 ρ 才能比较。

一个候选 = 一个点。x 读数来自区间长度，y 读数来自密度；r 只参与计算，不直接占一条轴。

code plane vs. objective plane
(L, r) 高度是 r　　密度 = 斜率
(L, ρ) 高度就是判据

代码内部用 (L, r) 做整数运算；画图时用 (L, ρ) 更直观。两者保留的是同一批点：斜率创新高 = 密度创新高。

不是在全基因组上找区间，而是在一个可疑窗口里，把“以 finish 结尾的所有后缀”逐个切出来。

配对数 r 是增量算出来的

向左吃进一个新的 3-mer w 时，它只和右侧已有的 w 配对。所以 r_new = r_old + count_old(w)，一次加法即可，不需要重新扫整段序列。

代码里就是 win_pairs += win_counts[word] 再 win_counts[word] += 1。 这也是为什么枚举所有起点仍然便宜：每个候选点 O(1) 更新。

incremental pair count
rnew = rold + countold(w)

新 3-mer 与旧后缀里每个相同的 3-mer 各形成一对；旧后缀内部的配对已经算过。

候选门控 不是每个后缀都值得比较。先算 10r > T·L（默认 T = 20，等价于 ρ > 2）； 不满足就直接跳过，不会成为图上的候选点。所以候选点全部落在门控线以上。
为什么右端固定 算法用滑动窗口扫描序列。右端固定时，所有候选共享同一个 finish，长度与起点一一对应， 比较就退化成一条一维的“长度轴”。窗口滑走之后，已确定的区间会被输出并与相邻区间合并。

示例参数：窗口内 64 个 3-mer 位置（约 66 bp），T = 20；默认窗口是 64 bp。表中只列出通过门控的 10 个候选；逐碱基扫描时，其余位置在门控处就被跳过了。

03
dominance

什么叫“被支配”：更短，而且不更稀

前沿不是“密度最高的点”，而是所有没有被别的候选在两个目标上同时压住的点。

设两个候选 A = (L_A, ρ_A)、B = (L_B, ρ_B)。若

dominance
LA ≤ LB　且　ρA ≥ ρB　（至少一个严格）

则 A 支配 B。B 被丢弃：不用更长的区间，就已经能得到不更低的密度。

因为所有候选共享右端，更短的区间一定是更长区间的后缀。A 更短且不更稀，意味着 B 多出来的那段前缀把平均密度拉低了； B 不能提供比 A 更强的低复杂度证据。于是 B 从“密度见证点”的集合里被删掉。

为什么只需要和一个点比较

在一次扫描内按 L 递增处理时，已保留点的密度是非降的，最后一个保留点就是当前纪录 (L*, r*)。 对任何更早的点 A，都有 L_A ≤ L* 且 ρ_A ≤ ρ*。

  • 若新点密度 ρ ≥ ρ*，它也不低于所有更早的点，不会被他点支配。
  • 若 ρ < ρ*，当前纪录点就直接支配它，无需再看别人。

所以每一步只做一次比较；“当前纪录”可以用一个分数 r*/L* 增量维护。

相等怎么办 严格 Pareto 会丢掉“同样密度但更长”的点。代码用的是 ≥，会把它保留下来： 同样的密度下覆盖更长，且最终合并不会产生额外区间，属于有意的 tie 处理。示例数据刻意没有相等值，台阶看起来更干净。

阴影 = A 支配的区域。注意：A 的“更短”是优势，所以阴影向右扩展；“不更稀”要求密度不高于 A，所以阴影向下扩展。

一句话 前沿 = 每一步的密度纪录。被纪录压住的点全部丢弃；新纪录点成为下一格的比较基准。

05
the actual code

落到代码：一次循环，两个整数条件

find_perfect 的核心只有四件事：增量更新、候选门控、取当前纪录、交叉相乘后入列。

src/lib.rs · find_perfect 省略了插入位置 j、start_i 与部分类型转换 
// perfect 按 start 降序（等价于按长度 L 递增）保存候选
for i in (0..=size - window - 1).rev() {
    // ① 向左吃进一个 3-mer：长度 +1，配对数 O(1) 更新
    let word = sliding.ring.get(i as usize) as usize;
    win_pairs += win_counts[word] as i64;
    win_counts[word] += 1;
    let new_win_pairs = win_pairs as u64;
    let new_len = (size - i - 1) as u64;

    // ② 候选门控：10r > T·L，等价于 ρ > T/10；不满足就跳过
    if (new_win_pairs as i64) * 10 <= total * new_len as i64 {
        continue;
    }

    // ③ 在所有“更短”的候选里取最高密度 r*/L*（最大值就是最后一个）
    for cur_perfect in &perfect[..j] {
        if cur_perfect.pairs as u64 * max_len > max_pairs * cur_perfect.len as u64 {
            max_pairs = cur_perfect.pairs as u64;
            max_len = cur_perfect.len as u64;
        }
    }

    // ④ 密度不劣于纪录 → 入列；r × L* ≥ r* × L，避免除法与浮点
    if new_win_pairs * max_len >= max_pairs * new_len {
        max_pairs = new_win_pairs;
        max_len = new_len;
        perfect.insert(j, Perfect { start: start_i, finish, pairs: new_win_pairs as u32, len: new_len as u32 });
    }
}

为什么用交叉相乘

比较 r / L ≥ r* / L*，两边乘以正数 L·L*，得到 r × L* ≥ r* × L。全程整数，没有除法、没有浮点误差，也没有除零特判。

纪录初始化为 0 / 1：任何正密度都会通过，所以第一个过门控的候选必然入列。 这正好是前沿的起点。

“更短”的范围

代码用 partition_point(|p| p.start >= start_i) 找到插入点 j， 只扫描 perfect[..j]——也就是起点在当前点右侧、长度更短的那些候选。 更长的候选不可能支配当前点，无需比较。

在一次扫描内，已保留点的密度随长度非降，所以这份最大值其实就是最后一个保留点； 代码写成重算，是为了不依赖列表里可能残留的旧窗口区间，也不依赖这个单调性。

06
edges & pitfalls

六个容易踩的边界

这些不是实现细节，而是“前沿到底是什么”的语义边界。

01 / UNIT

L 是 3-mer 数，不是碱基

前沿的横轴用 3-mer 个数；对应碱基跨度是 L + 2。阈值公式 10r > T·L 也使用同一个 L，不要混用。

02 / ORDER

必须按 L 递增扫描

从右向左，长度单调增加，才能只与“当前纪录”比较一次。乱序处理就必须与整条前沿比较，或者先排序。

03 / TIES

相等密度保留更长者

代码用 ≥，同密度下更长的点也入列。严格 Pareto 会去掉它；这里保留是为了覆盖更远，最终合并会处理嵌套。

04 / GATE

门控是严格大于

候选要求 10r > T·L，所以恰好等于 T/10 的点不会进入前沿。图上所有候选都严格在门控线之上。

05 / SCOPE

这是单窗口快照

前沿只回答“这个窗口里哪些后缀是密度见证点”。窗口滑走后，点被确定、输出、与相邻区间合并，才成为最终 BED 区间。

06 / FIRST

第一个点必然保留

纪录初始化为 0/1，任何正密度都满足 r·1 ≥ 0·L。因此第一个通过门控的候选就是台阶的起点。

回到两条轴 x 轴是 长度 L（越右越长，是代价）；y 轴是 密度 ρ = r/L（越上越密，是收益）。 前沿就是这两个目标下的非支配点集；构建它只需要一趟从左到右（按长度）的扫描，和一个不断被刷新的分数。
