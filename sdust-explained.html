rust port of lh3/sdust · byte-identical to dustmasker

把 DNA 里那些「没有信息量」的片段，
在一次线性扫描中指出来。

这个项目是 NCBI symmetric DUST 算法的 Rust 实现：输入 FASTA/FASTQ（可 gzip）， 输出低复杂度区间的 BED 坐标。它要同时满足三件互相拉扯的事—— 结果与业界事实标准 dustmasker 一致、能流式处理海量数据、还能作为库嵌进别人的流水线。

01
problem

问题：序列里的「噪声段落」会污染所有下游统计

基因组和测序数据中普遍存在低复杂度区域（LCR）：poly-A 尾巴、AT 二核苷酸串联重复、微卫星、低信息量的重复片段。它们不是错误，但几乎不含可用于区分的信号。

比对与组装失真

一个 20 bp 的 poly-A 能匹配基因组里成百上千个位置。种子（seed）在这些区域爆炸，导致 reads 被错误挂载、组装出嵌合 contig、或在该处堆积虚假 indel。

显著性模型失效

BLAST 一类工具的 E-value 建立在「随机背景序列」假设上。低复杂度区域偏离该假设，打分与 p 值不再可比，搜索结果被噪声淹没。

需要「标记」而非「删除」

软掩码（转小写）保留坐标与长度，硬掩码（换 N）彻底排除。两种做法都要求先拿到精确区间，所以输出必须是坐标，而不是过滤后的序列。

interactive
掩码对种子集的真实影响
12-mer 种子统计 · 点击开关，观察重复种子如何被清除

已有的答案，与它们的缺口

dustmasker（NCBI，随 BLAST 发行）：事实标准，但 C++ 实现、构建链重、难以嵌入自建工具。

sdust（Heng Li）：单文件 C 实现，极简，但只提供 C API；边界输入（损坏 FASTQ、非法参数）行为未定义。

本项目要填的格子

在 Rust 生态里提供一个行为可对拍、单遍流式、可复用缓冲的实现：CLI 与 C 版本逐字节一致，库接口则是 Rust 风格的（Interval / Masker），并且 #![forbid(unsafe_code)]。

02
method

方法：一次扫描，三次决策

整条流水线只有三个真正需要动脑的决策：用什么量衡量复杂度、怎么在滑动时增量维护它、什么时候可以把区间确定下来输出。点击每一步展开。

决策一：统计量选「配对」，不选「频次」

窗口内某个三联体出现 c 次，它对复杂度的贡献是 C(c,2) 对相同三联体。相比「出现次数的最大值」，配对计数对「一路重复下去」有二次放大：c 从 4 到 8，配对从 6 到 28。判定因此极其敏感。

决策二：阈值写成比值

10·r > T·n，其中 r 是配对总数、n 是窗口内的三联体位置数。左式与右式同阶增长，于是阈值等价于「重复率超过 T/10」，不随窗口长度漂移——这是窗口能从满长自动收缩到更短，而判定仍然可比的原因。

// 进：新词贡献的配对数 = 它此前的出现次数（O(1)）
ring_pairs += ring_count[word] as i64;
ring_count[word] += 1;

win_pairs  += win_count[word] as i64;
win_count[word]  += 1;

// 出：先把计数减一，再扣掉它此刻剩下的贡献
ring_count[oldest] -= 1;
ring_pairs -= ring_count[oldest] as i64;

// 全程没有对窗口的任何一次重扫

为什么是 3-mer

碱基只有 4 种，单碱基或二联体的重复在随机序列里也常见；四联体以上又会漏掉短重复。窗口内 3-mer 的配对计数对「短周期重复」（AT、AAG、ACGT…）都敏感，同时只有 64 个桶，计数表能整个放进 L1。

为什么能单遍

窗口向右滑时，进入一个新词、离开一个旧词，r 的增删都是 O(1)。只有当窗口「已经可疑」时才向左做一次回溯扫描（find_perfect），随机序列里这个分支几乎不触发。

为什么结果对称

配对计数只依赖三联体的重数分布。反向互补把每个三联体映射成另一个三联体，这是一一对应，因此 Σ C(cw,2) 完全不变——同一条序列正反链得到镜像一致的区间。

04
evidence

为什么可以信任它：把「一致」变成可执行的断言

正确性不靠论证，靠对拍。移植过程中与 C 版本做了逐字节差分；随机差分测试把长度 0–600 bp 的各种脏输入扫了一遍；这些结果的一部分被固化成夹具，每次 cargo test 都重新验证。

等价性验证

✓
90 组参数组合：-w ∈ {3,4,8,16,32,64} × -t ∈ {1,5,10,20,30}，FASTA / FASTQ / gzip 全一致。
✓
随机差分：串联重复、poly-A、N gap、大小写、多行 FASTQ，逐字节比对无差异。
✓
规模测试：5 Mbp 随机序列、3% 重复的基因组风格序列、20% 重复的高重复序列，输出全部一致。
✓
边界输入：BGZF 多成员 gzip、CRLF、多行质量值、缺结尾换行、前后垃圾字符。

刻意的差异（都是改好的地方）

→
损坏 FASTQ 报错：C 版本静默停止（退出码 0），这里报 truncated quality string 并以 1 退出。
→
参数校验：-w ∈ 3..=65535、-t > 0；C 版本 -w 0 会越界读。
→
CLI 是超集：长选项、-h/--help、-V/--version、多余参数报错。
→
Rust 风格 API：Interval{start,finish} 代替打包进 u64 的两个数；Masker 代替 sdust_buf_t；坐标上限 u32::MAX。

代价与边界

高重复输入（20% 重复的 5 Mbp）要 12.8 s：每个可疑位置都会触发一次 O(W) 的向左回溯。这是算法的固有成本，不是实现缺陷；随机序列只要 0.057 s。

内存

环形缓冲 O(W) + 64 桶计数 + 区间栈，与序列长度无关。因此可以处理「比内存大得多」的 FASTQ 流。

安全性

#![forbid(unsafe_code)]；Masker::mask 不 panic；非法参数由 Params::validate() 显式返回错误。这是「库」而非「脚本」的要求。
